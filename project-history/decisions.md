# 关键设计决策记录

## D1：纯静态演示原型

- **决策**：不依赖后端，使用 HTML/CSS/JS 三件套，数据存于浏览器 localStorage。
- **理由**：便于本地演示与快速评估设计；后续可平滑替换为真实后端与数据库。
- **影响**：登录、询盘、审核等均为前端模拟；真实邮件/消息需接入后端服务。

## D2：预发布审核流程

- **决策**：卖家发布的产品默认“待审核”，管理员通过后才对外可见。
- **理由**：满足内容审核的基本合规要求，规避违禁品/侵权内容风险。
- **配套**：内置违禁词扫描、侵权风险提示、审核通过/驳回与留痕。

## D3：贸易资讯栏目

- **决策**：以静态数据维护政策速览与信息源目录，每条附官方来源链接，支持分类/地域筛选。
- **理由**：权威信息可溯源、可审计；正式上线后可接入 RSS/官方 API 自动同步。

## D4：单证格式参考与打印

- **决策**：报价单/形式发票按国际贸易通行字段生成，使用浏览器打印“另存为 PDF”导出。
- **理由**：零依赖即可产出可留档的单证；字段参考美国商务部 trade.gov 等通行格式。

## D5：实时翻译服务栈

- **决策**：MyMemory（免费、免密钥、支持浏览器直连）→ LibreTranslate 公共实例 → 内置离线短语库。
- **理由**：真实翻译质量优先，无密钥需求；离线兜底保证断网可用。
- **配套**：译文全部标注“仅供参考，不构成要约或承诺”；结果本地缓存；请求超时保护。

## D6：多语言与“卖家语言 → 买家语言”

- **决策**：产品记录“源语言”（发布时选择，默认按卖家地区），浏览时按买家所选语言展示；
  中/英使用平台整理的双语数据，其他语言即时机器翻译并缓存。
- **理由**：卖家以母语发布、买家以母语阅读，是跨境贸易沟通的核心诉求。
- **配套**：详情页“原文”对照块；卡片标题三行换行、正文断词，为长译文预留版面。

## D7：首次访问默认英文

- **决策**：新访客默认英文界面，并显示轻量语言引导条（可一键选择语言或关闭）。
- **理由**：面向全球买家，英文作为国际通用引导语言；语言选择持久保存。

## D8：安全与合规边界

- **决策**：预发布审核、违禁词提示、用户协议/隐私/举报入口占位、单证免责声明、
  机器翻译免责声明、资讯来源可查询。
- **理由**：作为可评估原型，明确演示边界，避免误导为正式商业承诺。

## D9：防伪设计（品牌与产品验真）

- **决策**：为每件产品生成确定性唯一防伪码，详情页提供“扫码验真（演示）”与验证结果；
  页脚提供「防伪查询」与「验证本站真伪」入口，展示官方平台认证信息。
- **理由**：B2B 场景中买家最担心仿冒与钓鱼；低成本先建立“可验证”心智，
  正式版再接入权威验真机构、真实二维码与区块链存证。
- **配套**：防伪码由产品 ID + 卖家 + 标题校验生成；演示 QR 图案由防伪码种子绘制；
  全部文案多语言化并标注“正式版将接入权威验真服务”。

## D10：阶段 0 数据层抽象（契约先行）

- **决策**：先产出 ER 图、OpenAPI 接口定义与前端 `api.js` 数据层；
  页面数据访问统一收敛到 `window.api`，当前 mock 模式用 localStorage 模拟，
  将来切换 `API_CONFIG.mode='http'` 即接入真实后端。
- **理由**：把“数据来源”与“页面展示”解耦，后续技术选型或重写后端都不影响前端；
  同时为测试提供稳定的接口语义（Promise、错误码、延迟）。
- **配套**：`api:changed` 事件驱动页面重载重绘；冒烟测试（16 项）与页面回归（102 项）双验证。

## D11：后端阶段 1 MVP（零依赖先行）

- **决策**：先用 Node 内置 `node:http` + `node:sqlite` 实现完整业务闭环（零依赖），
  数据库按 ER 图建表、接口按 OpenAPI 实现；SQLite 仅用于本地开发/测试，
  生产 DDL 单独提供 PostgreSQL 版本。
- **理由**：无需联网安装依赖即可运行与测试，先验证业务与权限模型；
  避免过早绑定框架，阶段 2 再平滑迁移 NestJS/Express + PostgreSQL。
- **配套**：scrypt 密码哈希、HMAC 令牌、角色鉴权、审计日志、CORS；
  接口自动化测试 33 项断言全部通过。

## D12：阶段 1 增强与生产化

- **决策**：六个占位方向全部落地——翻译服务端代理（真实链+额度+缓存）、
  文件上传（本地存储+可换 S3）、WebSocket 实时消息、通知/邮件（mock 落库可切 SMTP）、
  接口分页、Docker 部署模板。
- **理由**：先以零依赖/本地实现把能力跑通并测试，再按部署指南逐项替换为外部服务，
  避免早期被云厂商绑定。
- **查漏补缺**：修复 WebSocket 会话外键崩溃；补充登录限流、上传白名单与路径穿越防护；
  全套 160 项测试通过（后端 42 + 前端 118）。

## D13：真实通道就绪（DeepL + SMTP）

- **决策**：翻译主通道切换为 DeepL（密钥配置驱动，chain 模式自动降级 MyMemory/Libre/离线）；
  邮件实现零依赖 SMTP 客户端（STARTTLS/AUTH PLAIN），结果落库可审计。
- **理由**：生产质量优先于“能跑”：DeepL 翻译质量与合规更好，SMTP 直连不引入额外依赖；
  密钥全部走环境变量，不进代码与仓库。
- **验证**：用本地假 DeepL 端点与假 SMTP 服务器做协议级测试（后端共 53 项通过）；
  真实调用只需在 `backend/.env` 填凭据并联网。
