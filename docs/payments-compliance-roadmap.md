# 支付与金融合规路线图（框架）

> 状态：2026-08-18 建立框架。平台当前**不处理真实资金**（交易与打赏均为演示数据）。
> 上线支付/托管/佣金前，必须先完成下列合规要求；本文件作为施工蓝图与审计清单。

## 1. 原则（写进代码与合同）

- 平台不触碰用户资金：资金由持牌支付机构/托管账户存管，平台只传递指令与记账。
- 用户资金与平台运营资金严格隔离（信托/托管账户）。
- 未经持牌机构或支付服务商（PSP）接入，前端禁止出现任何"付款/收款"真实入口。
- 所有费率、佣金、打赏结算必须明示并写入用户协议与订单页。

## 2. 必须遵守的法规（按目标市场分阶段）

| 区域 | 法规 / 牌照 | 关键要求 |
| --- | --- | --- |
| 中国 | 非银行支付机构条例、跨境支付展业规范 | 不得无证从事资金结算；跨境支付需持牌或通过持牌机构通道 |
| 美国 | MSB 牌照（FinCEN）、州级 Money Transmitter License | 反洗钱（AML）计划、可疑交易报告（SAR）、客户识别（KYC） |
| 欧盟 | PSD2 / EMI 牌照 | 强客户认证（SCA）、资金保护、透明度 |
| 香港 | MSO（金钱服务经营者）牌照 | 牌照申请、AML/CFT 合规负责人 |
| 新加坡 | PS Act（MAS） | 支付机构牌照、用户资金保障 |
| 通用 | FATF 建议、GDPR/个保法 | 客户尽职调查（CDD）、数据最小化与跨境传输合规 |

## 3. 技术合规清单（开发前逐项勾选）

- [ ] 支付服务商选型：Stripe / Adyen / Airwallex / Payoneer / 中国跨境支付机构（需商户主体）。
- [ ] PCI DSS：卡数据不经前端/平台服务器（用 PSP 托管表单或令牌化）。
- [ ] 托管交易：资金进入 PSP 托管账户，买家签收后释放给卖家（Escrow 流程）。
- [ ] KYC/AML：个人/企业实名、受益所有人（UBO）、制裁名单与负面新闻筛查（可用第三方合规服务）。
- [ ] 反欺诈：风控规则（设备指纹、交易频次、地址一致性、拒付率监控）。
- [ ] 结算与对账：日切对账、退款、拒付、税费（增值税/销售税自动计算）、佣金抽成流水。
- [ ] 数据安全：加密存储、密钥托管（KMS/Secrets Manager）、日志审计（不可篡改）。
- [ ] 法律文本：用户协议、隐私政策、服务条款、托管协议、保险条款、争议处理规则（双语）。
- [ ] 消费者保护：冷静期/退款政策（适用区域）、投诉渠道、监管备案公示。

## 4. 分阶段落地计划

### 阶段 A（无主体，不收款）
- 保持演示模式；页面明示"暂不支持真实支付"。
- 保险只做试点框架（本仓库已实现 `/insurances`）；合同保管只做电子哈希留痕。
- 完成本文件第 3 节中与主体无关的合规文本与风控规则设计。

### 阶段 B（有海外公司主体后）
- 注册支付账户（建议 Airwallex / Stripe 多币种），完成 KYC。
- 接入 PSP 托管支付 + 退款 + 对账 API；佣金与打赏走 PSP 子账户/分账。
- 上线前通过安全体检（可复用 `docs/security-best-practices-report.md`）并补充支付专项渗透测试。

### 阶段 C（规模化）
- 按主要营收市场申请/备案牌照（美 MSB / 港 MSO / 欧 EMI 任选其一作为枢纽）。
- 引入持牌保险合作商（`insurance_providers` 表已预留），展示牌照与备案。
- 建立合规官岗位或外包合规服务，接入监管报送。
